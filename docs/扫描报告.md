# 残留英文全量扫描报告

> 目标：用"通关残局存档 + 脚本遍历"把 DOM 里每一段可见文本都过一遍，列出残留英文并一次性补齐。

## 方法

1. **造残局存档**：从游戏自身导出的默认存档（`mg98-save-v4`）反推 schema，构造两份状态：
   - `tools/exprs/preload_max.js` —— 10/10 阶段通关、全部建筑建成、全部升级拉满、全资源 800+、七种玉石/种子齐全、动物已解码放生、发射完成 2 次；
   - `tools/exprs/preload_busy.js` —— 在上面的基础上进入"忙碌态"：沙尘暴激活、火箭飞行中、解码倒计时进行中、培养托盘成熟、手动摇泵中（这几种状态只在运行中短暂出现）。
2. **注入存档**：`tools/shot.mjs` 用 CDP 的 `Page.addScriptToEvaluateOnNewDocument` 在页面脚本执行前写好 localStorage，游戏启动即读档（`RELEASE=false` 才会走 `load()`）。
3. **遍历采集**：脚本依次点开 7 个标签页、每个标签页里全部蓝图卡片（读 `#bp-detail`）、6 个菜单及其中每个菜单项（任务简报/报告/开发套件/导出…）、工具栏帮助与"向斯普罗凯特要提示"、以及采矿按钮（抓浮动数字），每一步都用 `TreeWalker` 把 DOM 文本节点 + `title/aria-label/alt/placeholder` 属性全量收集。
4. **回读**：结果 base64 编码后经 `--evalout` 落盘，避免长字符串在管道里被截断。

## 修掉的两个通用 bug

1. **规则误命中**：`^(.+) ore$/i` 会把任何以 "Ore" 结尾的长句（如配方行）截断成 `... Copper矿`。现在改成只在 `DICT[前缀 + " Ore"]` 能查到具体条目时才替换。
2. **守卫规则被当命中**：规则里"查不到就返回原文"的守卫，原来仍会走一遍 `embed()`，把 `Thorium Rods in stock…` 改成 `钍棒s in stock…`。现在 `out === key` 视为未命中，继续尝试下一条规则。

## 第四轮：按钮上的"电力不足"（第十一轮）

`#mine-btn` 的内容是 `NOT ENOUGH POWER (need ${eIco(...)})`，而 `eIco()` 会插一个 `<span class="eamt"><img>1.0 E</span>`，于是这条文本被切成三个节点：

```
"NOT ENOUGH POWER (need "  +  [⚡1.0 E]  +  ")"
```

原来的规则要求结尾带右括号，永远匹配不到第一个节点。补法：

1. 前缀规则 `^NOT ENOUGH POWER \(need\s*$` → **电力不足（需要**（不带右括号）；
2. 末尾那个孤立的 `)` 节点单独处理成全角 `）`（`minebtn()`，只对 `#mine-btn` 生效）；
3. 同时保留整串匹配版本，兼容没被图标切开的情况。

实测（`preload_lowpower.js`：能量 0、无太阳能板、无 RTG）：

```
#mine-btn 文本 = "电力不足（需要 1.5 能量）"
clientWidth = 223 / scrollWidth = 223   → 不溢出、不截断
```

另外这个状态也验证了"断电"分支下的其它文案：`基地电网输出偏低。`、`电力不足，无法采矿。` 均为中文。

## 第六轮：建造格上的 `NOT IN DEMO`（大小写索引 bug）

现象：蓝图格子里的标签仍显示 `NOT IN DEMO`，而旁边的 `LOCKED` 已经是「未解锁」。

根因：翻译层有一个大小写无关索引 `LOWER`（`NOT IN DEMO` → 命中 `Not in demo` 词条），但它在**文件前部**就构建完了，而后几轮用 `Object.assign(DICT, …)` 追加的词条（包括这次新加的 `Not in demo`）都在它**之后**，所以永远进不了索引——大写/变体的文案因此查不到。

修法：在导出 `window.MGI18N` 之前重建一次索引：

```js
LOWER.clear();
for (const k in DICT) { const lk = k.toLowerCase(); if (!LOWER.has(lk)) LOWER.set(lk, DICT[k]); }
```

顺带确认这条 bug 也影响其它"后加词条 + 大写文案"的组合（`MAX`/`RETIRED` 等），修完后全部命中。

复扫结果（通关态）：纯英文残留只剩 3 条 —— `STEAM`、`CO₂ / N₂`、`Ctrl+S`；其余 7 条是中英混排（`Demo 版不可用`、`CAM-01 · 基地营`、`发射综合体 LC-1` 等），属正常。

## 第七轮：解锁框（`unlockBox`）整块漏译

用户截图里的「改造钻机已建成」弹窗：

```
★ 3 NEW UNLOCKS
新矿石：钍矿        / Dig it in the Mine tab.
新配方：钍棒        / Craft it in the Refinery.
New tab: Terraform  / Load Thorium Rods into the drill here.
```

**为什么漏**：`unlockBox(items, head)` 是一个独立的小组件，条目文本作为数组参数传进去：

```js
unlockBox([
  [ORES.thorium.i32, 'New ore: Thorium Ore',     'Dig it in the Mine tab.'],
  [URL_.rod,         'New recipe: Thorium Rod',  'Craft it in the Refinery.'],
  [URL_.tdrill,      'New tab: Terraform',       'Load Thorium Rods into the drill here.'],
])
```

- 标题行是 `★ ${n} NEW UNLOCKS`，带 `★ ` 前缀，原有规则 `^(\d+) NEW UNLOCKS?$` 匹配不到；
- 三条描述是**独立的短句**，词典里没有；`New tab:` 这个前缀也没有对应规则；
- 之前的 DOM 扫描没有覆盖这条路径——它只在「建造改造钻机」这一瞬间出现，两份残局存档都已经是建成状态。

**修法**：
1. 加 `★` 前缀剥离规则：`^★\s*(.+)$` → 递归翻译后半段再加回 `★ `；
2. 加 `New tab: X` / `New machine: X` / `New unlock(s): X` 三条前缀规则；
3. 补 3 条整句：`Dig it in the Mine tab.`、`Craft it in the Refinery.`、`Load Thorium Rods into the drill here.`

**验证**：新建 `tools/exprs/preload_drill.js`（`built.drill=false` + 阶段 3 + 资源充足），走真实 UI 路径点「建造改造钻机」，读回弹窗文本：

```
title: 改造钻机已建成
body : 你建起了改造钻机，现在可以开始改造这颗行星了。 ★ 3 项新解锁
       新矿石：钍矿 在矿井页挖到它。
       新配方：钍棒 在精炼里制造它。
       新页面：地形改造 在这里给钻机装填钍棒。
```

**顺带补的流程漏洞**：这类"只在一瞬间出现"的弹窗，残局存档扫不到。现在 `preload_drill.js` + `tools/exprs/unlock_probe.js` 作为固定的建造弹窗回归用例保留。

回归扫描（通关态）：纯英文残留仍为白名单 3 条（`STEAM` / `CO₂ / N₂` / `Ctrl+S`）。

### 顺带修掉的两个通用 bug

1. **`embed()` 过度替换**：词表按数组顺序替换，`Water` 排在 `Water Pump` 前面，于是 `Water Pump` 先被切成 `水 Pump`、`Liquid Water` 变成 `Liquid 水`。改成**按词长降序**替换即可。
2. **贪婪规则产出半中半英整段**：段落级替换先调用 `tr(整段)`，而 `^Next · Stage (\d+)/10: (.+)$` 会把整段吞进 `(.+)`，只译了前半句就写回 DOM。现在加守卫——替换结果若仍含「两个以上连续英文单词」，就放弃整段、退回逐节点翻译。

`Greenhouse Charge` 早期误作「温室染料」，与 `Greenhouse Charges`「温室装药」不一致，已统一为**温室装药**。
