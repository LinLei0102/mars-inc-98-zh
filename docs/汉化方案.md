# Mars Inc 98 多语言（汉化）可行性分析

结论：**能做，而且已经跑通了一版可玩的中文化外壳。** 但"汉化"在这份代码里不是加一行 `i18n` 就完事的活——它没有语言抽象层，全部文案是硬编码英文；能不能汉化，取决于你愿意在哪一层拦。

本文所有数字都来自对 `src/game.pretty.js`（12,663 行）和 `index.html` 的实测，以及 Edge 无头浏览器里真实跑起来的中文版截图。

---

## 一、先给结论

| 问题 | 答案 |
|---|---|
| 技术上能不能中文化 | 能，三条路都走得通，最轻的一条（零改源码 + 12 KB 翻译层）已经实测可运行 |
| 有没有现成的 i18n | 没有。0 处 `t()` / `lang` / 语言包，89 处 `log()` 与 527 处模板字符串全部硬编码英文 |
| 内容是不是数据驱动 | 是。57 张常量表（`ORES`/`UPG`/`BLUEPRINTS`/`SEEDS`/`STAGES`/`GOALS`/`ANIMALS`…），改表比逐句改代码划算 |
| 需要翻译多少 | 去重后 **865 条**可读文案；其中 219 条在数据表里（好改），646 条夹在渲染模板和日志调用里（要包 `T()` 或者用 DOM 层兜） |
| 会不会被排版撑坏 | 实测 1500×950 无溢出；但 tab/按钮有 `min-width:58px` 和 `white-space:nowrap`，个别长译名要抽查 |
| 中文字体 | 要补。UI 用的是 Tahoma/MS Sans Serif 栈，LCD 数字用 VT323（无 CJK），需在 `--font-ui` 加中文像素字体回退 |
| 存档会不会挂 | 不会。`SAVE_KEY = mg98-save-v4` 只存数值和 flags，与语言无关，切语言不动存档 |

## 二、实测证据（已经做出来了）

`i18n/zh-CN.js`（12 KB，零源码改动）挂在页面上之后，在真实浏览器里启动游戏：

- 运行时统计：**命中 210 条 / 未命中 9 条**
- 未命中的 9 条全部是**叙事内容**（任务简报正文 "Earth is dying…"）和一处逐字母动画的 "STEAM"，不是机制问题
- 界面壳层：菜单栏（文件/视图/殖民地/建造/选项/帮助）、工具栏（制造/太阳能/帮助）、面板标题、建造格、合成表、资源列、日志、任务目标、阶段 HUD **全部中文**
- 布局：1500×950 和默认窗口下都没有溢出、错行、按钮被撑破

对比截图：`shots/en_ui.png`（英文原版） / `shots/zh_final.png`（中文版）。

## 三、代码结构决定了"能怎么做"

### 1. 文案是数据驱动的（好消息）

内容集中在常量表里，每项都是对象 + 函数：

```js
// game.pretty.js:2989 起
const UPG = {
  bit: {
    name: "Common Ore Drill Bit",
    short: () => "Dig more Iron and Silica with each click.",
    verb: "Upgrade",
    desc: () => `Upgrades every Common ore (${CLASS_ORES(1)}): +1 ore per click`,
    ...
```

同构的表还有 `NAMES`(2293)、`ORES`(2213)、`STAGES`(2339)、`BLUEPRINTS`、`RECIPES`、`SEEDS`、`ANIMALS`、`GOALS`(5442)、`CHECKS`、`TAB_NAMES`(7080)、`MENUS`(7073)、`HELP_ITEMS`、`PHASES`(2441)。
**改一张表 = 汉化一整类内容**，这是可行性的地基。

### 2. 渲染入口很集中（也是好消息）

文本只从几个口子出去：`setText()`(3616)、`nm()`(3620)、`log()`(2844)、`dialog()`(7471)、`D()`(5808)、以及 36 处 `innerHTML =` 的大模板。
意味着只要在 5～6 个函数 + 一批模板外层插 `T()`，就能覆盖 95% 的文本。

### 3. 但有四个坑，直接决定了方案选型

| 坑 | 现象 | 对策 |
|---|---|---|
| `.toUpperCase()` 拼接 | `STAGE 1/10 · PRESSURE`、`BUILD MINING RIG`、`MINE IRON ORE · 1 E`、`EN ROUTE · …` 都是先转大写再显示 | 查表必须**大小写不敏感**；否则永远匹配不上 |
| 逐字母 span | 标题界面 "WISHLIST ON STEAM" 是一个字母一个节点（动画），整块查表失败 | DOM 层覆盖不到，必须在源码里改这一处 |
| 数字/单位格式化函数 | `STAT_FMT`(2647)、`UNIT`(2326)、`fmt`(2824)：`v+" mbar"`、`v+"% life"`、`" L"` | 单独做单位映射 + 数值正则规则，不能靠整句词典 |
| 文案被标签切碎 | 菜单 `<u>F</u>ile`、按钮里插 `<img>` | 需要"合并元素文本再译"的二次扫描，且只能对按钮类元素做，否则会把相邻字段粘成一串 |

### 4. 字体与排版

- `--font-ui: Tahoma, "MS Sans Serif", Geneva, "Segoe UI", Verdana, sans-serif` → 中文走系统回退，能显示但不是像素风；要还原 Win98 观感建议补 **Zpix / 缝合像素字体 (Fusion Pixel)**。
- `--font-lcd: "VT323"` 只用于大号数字，无 CJK，不用管。
- 面板是固定格栅，中文一般比英文短，实测无溢出；风险点只有 `min-width:58px` 的按钮和 `.tab` 的 `white-space:nowrap`。

## 四、三条路线，对比着选

| | A. 运行时 DOM 翻译层（已实现） | B. 源码加 `T()` 抽象 | C. 数据表 + 构建期整体替换 |
|---|---|---|---|
| 改什么 | 0 行游戏代码，加一个 12 KB 脚本 | 改 5～6 个渲染函数 + 约 646 处模板/日志 + 57 张表字段 | 只改常量表 + 少量格式化函数；模板句子用构建期正则替换 |
| 覆盖度 | 立刻 100% 的"能看见的文字"，包括弹窗、日志、tooltip | 100%，且可控 | 约 70%，模板里的整句仍要手改 |
| 维护性 | 差：作者一更新就重跑一遍报告，逐条补 | 好：与上游 diff 冲突少，可长期跟版 | 中 |
| 多语言切换（en/zh 并存） | 能（`?lang=en` 已支持） | 最干净 | 需要打两份包 |
| 性能 | 噪声：每帧重绘触发查表，实测无感（查表是 Map + 正则，且带 CJK 短路） | 零额外开销 | 零额外开销 |
| 风险 | 译文被后续重绘覆盖（已用 MutationObserver 解决）；个别逐字母动画失效 | 改动面大，容易漏 | 正则误伤 HTML 结构 |
| 适合谁 | 想**今天就看到中文**、不打算跟版 | 要做**正式发布的中文版** | 只想快速出个能看的包 |

**推荐：A 打底 + B 收尾。**
先用 A 在一天内把整个界面变成中文、把剩下的英文全部"捞"出来（`MGI18N.report()` 直接给未命中清单），然后把叙事/教程这批长文案按 B 的方式落到源码里，最后 A 退化成兜底。

## 六、真要落地，按这个顺序做

1. **定基线**：`node build.mjs` 出英文原版，留作 diff 基准。
2. **补字体**：`src/style.css` 的 `--font-ui` 前置中文字体，`letter-spacing:0` 避免像素字错位。
3. **刷数据表**：`NAMES`/`ORES`/`UPG`/`BLUEPRINTS`/`SEEDS`/`ANIMALS`/`GOALS`/`STAGES`/`PHASES`/`TAB_NAMES`/`MENUS`。这一层做完，界面已经七成中文。
4. **包 `T()`**：给 `setText`/`nm`/`log`/`dialog`/`D` 五个出口加钩子，模板句子改 `T('Batteries at {0}%', v)` 形式。
5. **处理三个特例**：`.toUpperCase()` 的 4 处、Wishlist 逐字母动画、`STAT_FMT`/`UNIT` 单位。
6. **回归验收**：8 个标签页 × 每个交互一次 + 弹窗/日志 + 存档读档 + 1500/1280/960 三个宽度。
7. **打包**：`node build.mjs --zh` 出 `dist/index.zh.html`（单文件 3.64 MB），按 itch.io HTML 游戏上传。

## 七、现成的坑清单（踩过了，别再踩）

1. `RELEASE=true` 时 Debug 菜单和存档被删掉，调参先在本地改 `false`。
2. `buildItchZip()`（2259 行）会在运行时把 `RELEASE=false` 改 `true` 打包——**别指望用它的导出功能保留中文补丁**，它读的是页面里的原始脚本。
3. `renderAll` 每 500 ms 跑一次，DOM 层翻译必须走 `requestAnimationFrame` 批处理 + "已含中文就跳过"的短路，否则会打摆子。
4. 只对 `<button>`/`.tab`/`.tile` 做"合并文本再译"，对容器做会把相邻字段粘成 `Fog Clearance0.0%`。
5. 单字符文本（逐字母动画）不要进词典，会把统计和性能都搞脏。
6. 中文不要进 `toUpperCase()` 路径的模板——虽然无害，但会暴露你改过源码。
7. 作者更新后，`game.js` 会整体被替换：DOM 层方案只需重跑报告补词条，源码方案要重新打补丁。

## 这轮做了什么

1. **量化抽取**：写了一个不用正则一把梭的 JS 词法扫描器（处理模板字符串嵌套、`\${}` 表达式、注释），从 4,336 个字面量里挑出 1,014 条候选 UI 文案，过滤掉选择器/类名/CSS 后剩 936 条。
2. **全量翻译**：按索引分批译完 742 条，合并进 `i18n/zh-CN.js`（`#` 占位符自动转成带捕获组的规则）。
3. **运行时加固**：把翻译层从 "DOMContentLoaded + rAF" 改成 "立即扫描 + MutationObserver(微任务) + 700ms 轮询 + load/visibility 事件"，因为 itch.io 的 `htmlgame.js` 一旦加载失败，`DOMContentLoaded` 就永远不触发，rAF 在后台标签页也会被节流——这两个坑都会让翻译"看起来随机失效"。
4. **实机闭环**：`tools/shot.mjs` 用 CDP 驱动无头 Edge，解锁全部建筑、遍历 7 个标签页，通过 `document.documentElement.dataset` 回读未命中清单，迭代 4 轮把 39 条降到 3 条。

- **逐字母动画**：标题页 "WISHLIST ON STEAM" 与工具栏同款按钮每帧重建字母节点，只把动作词换成"加入愿望单 ·"，品牌字样保留英文。

## 第六轮（多段弹窗）

用户反馈的「The 矿井 页已打开。／下一个目标：建造 改造钻机。」是**多段弹窗**：

```js
D("Mining Rig Built", `<p>The <b>Mine</b> tab is now open.</p><p>Next goal: build the <b>Terraform Drill</b>.</p>`)
```

逐文本节点翻译会把 `The` 留在英文、`tab is now open.` 译成"页已打开"，拼出来就是半中半英。

修法（两层）：

1. **块级感知归一化 `normText()`**：遍历子节点时在 `P/DIV/LI/BR/OL/UL/H1-6` 等块级边界补空格，否则 `textContent` 会把两段粘成 `…open.Next goal…`，永远匹配不上。
2. **段落级整句替换**：`.dlg-body` 内的 `<p>`/`<li>` 在递归前先按 `normText` 查表，命中就整段替换（`textContent` 写入，中文不需要保留加粗）；查不到才回落到逐节点翻译。

补的整段词条：`The Mine tab is now open.`、`Next goal: build the Terraform Drill.`、`You built the Terraform Drill. You can now begin terraforming the planet.`、`The Heater is ready. …`、`The hand pump is in. …`、`Unlocked:`、`7 more stages…` 等 14 条。

实测注入两个真实弹窗 HTML（`#modal`）后读回：
- `矿井页已经打开。 / 下一个目标：建造改造钻机。`
- `你建起了改造钻机，现在可以开始改造这颗行星了。`

全解锁遍历 7 个标签页仍是 **100%**，未命中仅剩 `STEAM` 品牌字样与两条沙尘暴临时块。


## 第七轮（采矿面板的数值+单位文案）

用户截图里 Mine 页残留的英文，全部是**数值与单位拼接**出来的，词条表里查不到：

| 原文 | 现在 |
|---|---|
| `Common ore`（矿牌徽章） | `常见矿` |
| `1 ore for ⚡1.0` | `1 矿石 · 耗 ⚡1.0` |
| `0 on hand` | `0 在手` |
| `1 ore · Common ore`（每次开采产量） | `1 矿石 · 常见矿` |
| `MINE IRON ORE · ⚡1.0` | `开采铁矿 · ⚡1.0` |
| `1 ore / click`（手动产量） | `1 矿石/次` |
| `0.00 ore / s`（无人机速率） | `0.00 矿石/秒` |
| `parked` | `已停泊` |
| `AUTO` 徽章 | `自动` |

做法：新增 11 条带捕获组的正则规则，注意两点坑——

1. 数字前缀要单独匹配：`^(.+) on hand$` 会把 `0` 交给 `tr()`，而 `tr("0")` 原样返回，守卫条件直接判"未翻译"；必须写成 `^([\d.,]+) on hand$`。
2. 规则替换值不要自带尾随空格，`tr()` 已经保留原文首尾空白，否则会出现双空格。

验证方式：解锁全部建筑后遍历 7 个面板，逐面板抓 `innerText` 里的拉丁字母片段——结果 `power / mine / terra / hydro / bio / launch` 全部为 **0 条**，`craft` 只剩 `CAM-01`（摄像头编号，本就该保留）。
